03 / Field notes

A few things we're thinking about.

Short reads on making software more useful, humane, and easier to live with.

06.18.26 DESIGNThe best feature might be the thing you remove+

Every product accumulates decisions. A setting here, a shortcut there, one more option for the edge case. Eventually the interface starts asking people to understand the system before they can get anything done.

Before adding another control, look for the friction underneath the request. Often the better fix is a clearer default, a missing connection, or a step that no longer needs to exist. Subtraction isn't a style choice. It's a way to give someone's attention back.

05.02.26 PROCESSStart with the handoff, not the software+

When a process feels broken, it is tempting to start by listing features. Start instead with the moment work changes hands. What does the next person need to know? What gets lost, delayed, or copied by hand?

That small bit of fieldwork often reveals the real shape of the problem. Software can make a good handoff easier, but it cannot decide what a useful handoff means for your team. Learn that first, then build just enough to support it.

03.14.26 ENGINEERINGA useful prototype is a question you can click+

A prototype does not need to predict the finished product. It needs to make an important uncertainty visible. Can a person find the next step? Does this data belong together? Is this workflow actually faster?

Make the smallest thing that lets someone answer honestly. Then watch them use it. The point isn't to fall in love with the prototype; it is to learn what deserves the effort of becoming real.
